# antislop audit-001 — Optimize page

- **Date:** 2026-11-28
- **Scope:** `OptimizePage` in `app/ui/app.slint` (+ shared `RiskBadge`, confirm overlay, `app/src/main.rs` wiring for tweaks)
- **Mode:** AFTER
- **Direction:** no `DESIGN.md`; Apple HIG used as requested UX reference (not a visual clone)
- **Design Read (for later fixes):** system utility screen for gamers/power users, calm dense tool language, dial ENERGY 1 / RHYTHM 2 / MOTION 1

Priority: Hard Gate = HIGH · Purpose-Gate = MEDIUM · Quality Locks / Apple HIG craft = LOW (unless mapped to Hard Gate)

---

## Findings

### 1. HIGH — R-27 — Missing empty / loading / error states on Optimize

`OptimizePage` only disables buttons when `busy`. Unlike Cleanup, there is no in-page progress, no empty list state, and no error surface. Success/failure for Apply / Revert / Restore Point is pushed to sidebar `status_text` only. A UI with data and destructive actions needs the three states on the page itself.

### 2. HIGH — R-26 / C-2 — Apply stays enabled with nothing selected

`Apply selected` remains enabled when the selection is empty. `apply_selected([])` still creates a restore point path and returns a “success” backup with no tweaks. That is a dead/misleading primary action. Disable when `selected.count == 0`, or show clear in-page feedback.

### 3. HIGH — R-26 / Apple HIG Destructive Actions — Revert all has no confirmation

`Revert all` immediately runs `revert_all()` with no confirm dialog. It undoes system changes from the latest backup. Apple HIG requires an explicit confirm for irreversible or high-impact actions. Cleanup/Apply already use `show_confirm` for risky paths; Revert should too.

### 4. HIGH — R-39 / R-32 — List rows are not keyboard-operable as units; nav is `TouchArea` on `Rectangle`

`SideNav` and tweak rows rely on `TouchArea` / checkbox only. There is no focus ring contract beyond std-widgets defaults, no row-level activation, and no Escape handling documented for the confirm overlay beyond button clicks. Focus visibility and operable semantics for custom chrome are incomplete for keyboard-only use.

### 5. HIGH — R-38 / i18n honesty — Risk badges and status chrome ignore locale

`RiskBadge` renders raw English keys (`safe` / `moderate` / `risky`). Confirm copy for risky apply, Apply/Revert/Restore status strings in `main.rs` are English-only. Russian UI still shows English risk chips and English confirm/status. Labels must be translated or honest placeholders, not mixed-language chrome.

### 6. MEDIUM — R-14 / R-05 — Flat identical card list ignores real hierarchy

~24 tweaks with categories (`Gaming`, `Input`, `Visual`, …) and three risk tiers render as one uniform bordered card stack. Backend already has `TweakCategory` and `Risk`, unused in layout. Apple Settings pattern: inset grouped list by section (risk or category), not clone-stamped cards. Uniform cards without a written hierarchy reason fail the purpose test.

### 7. MEDIUM — R-09 / R-31 — Status chips (`reboot`, `applied`) are weak, unlocalized micro-labels

Lowercase `reboot` / `applied` sit as plain `Text` with no badge structure, no accessible name beyond the string, and no clear relationship to the row action model (selected vs already applied). Purpose is status, but the treatment is unfinished and easy to miss.

### 8. MEDIUM — R-12 / R-14 — Every row is an elevated bordered card

Full-bleed cards with border + elevated fill on every tweak add noise without hierarchy. Apple HIG grouped lists use separators / section backgrounds, not floating cards for each row. Shadow/border elevation should mark sections or the toolbar, not every item.

### 9. LOW — R-15 / Apple HIG Clarity — Toolbar actions lack hierarchy and context

Three peer buttons: Apply / Revert all / Create restore point. Primary is set on Apply, but there is no selection count (“Apply 5”), no secondary placement for safety actions, and restore point (safety) is equal weight to revert (destructive). CTAs should state the concrete action and risk posture.

### 10. LOW — R-20 / R-31 / Apple HIG Content Hierarchy — Page header is generic tool chrome

Title + one muted subtitle, then buttons, then infinite list. No summary of applied count, selected count, or risk mix. No large-title / inline toolbar relationship. The screen does not communicate “what is my machine state” at a glance; only a dump of toggles.

### 11. LOW — R-03 / layout resilience — Fixed 360px name column + elide

Name is hard-capped at `360px` with elide. At `min-width: 900px` with a 200px sidebar this truncates long RU/EN tweak names. Prefer flexible column with wrap or two-line title instead of a fixed width that fights localization.

### 12. LOW — R-21 / R-34 — Dark-only theme with no toggle

Dark default is defensible for a system/gaming utility, but there is no light mode and no documented brand reason in `DESIGN.md` (file missing). Either document the dark-only choice or ship a working toggle. Noted for Optimize as it inherits app shell theme.

### 13. LOW — Apple HIG Progressive Disclosure — Risky tweaks not gated in the list

All Safe / Moderate / Risky items appear equally selected-capable in one scroll. Safe defaults to selected in code; Risky sits in the same visual band. Apple pattern: segment or filter (All / Safe / Moderate / Risky), or Risky behind an explicit Advanced disclosure, so risk is a first-class navigation choice.

### 14. LOW — C-3 / R-05 — Description always fully expanded

Every row always shows full `description`, making the list tall and hard to scan. Prefer primary label + secondary one-liner, detail on focus/expand, matching Apple Settings secondary labels.

### 15. LOW — R-37 — No `DESIGN.md` / brand dials for Recleaner UI

Optimize (and the shell) were built without recorded design direction. Fixes in AFTER mode should establish dials and a short `DESIGN.md` before visual rework, or label drafts as without direction.
