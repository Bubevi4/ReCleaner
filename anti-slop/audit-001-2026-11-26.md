## Findings

### 1. Settings page stretches into empty space
- **Priority:** HIGH
- **Rule:** R-05, C-1
- **Where:** `SettingsPage` in `app/ui/app.slint`
- **Why:** Unlike Cleanup/Optimize/Startup (which park leftover height in a `ScrollView` with `vertical-stretch: 1`), Settings has no stretch sink. The page fills the content pane and Slint distributes extra height between children, so Language, path, and disclaimer float apart. Matches the sparse Settings screenshot.

### 2. Language controls are oversized for their labels
- **Priority:** HIGH
- **Rule:** R-05, R-31
- **Where:** `SettingsPage` language `Button` pair
- **Why:** Std `Button` widgets expand with the layout. Short labels ("English" / "Русский") sit in large empty hit areas; selection reads as two giant slabs, not a compact control group aligned under the section label.

### 3. Settings content is not grouped
- **Priority:** MEDIUM
- **Rule:** R-20, R-31
- **Where:** `SettingsPage`
- **Why:** Language, config path, and MIT/risk note are three loose `Text`/`Button` stacks with no section frame, max-width, or footer pin. Hierarchy is weak next to Cleanup’s tight header → actions → list.

### 4. Em dashes in user-visible copy
- **Priority:** HIGH
- **Rule:** R-02
- **Where:**
  - Settings string: `Open source MIT... — confirm...` (+ RU msgstr)
  - Empty size placeholder in `app/src/main.rs` (`"—"`)
- **Why:** Hard Gate forbids em dash (`—`) in agent/product UI text. Replace with en dash alternative that is not em, or hyphen/colon wording (e.g. `-` or rephrase).

### 5. Split accent identity (green theme vs blue primary buttons)
- **Priority:** MEDIUM
- **Rule:** R-29, R-20
- **Where:** `theme.slint` (`accent: #3ecf8e`) vs std-widgets primary buttons (blue in screenshots) vs risk badges (green/amber/red)
- **Why:** Active palette reads as two competing accents. Cleanup’s “Clean” and Settings’ selected language use blue; badges use green. Palette needs one deliberate accent.

### 6. Missing empty / error states on list pages
- **Priority:** HIGH
- **Rule:** R-27
- **Where:** Cleanup / Optimize / Startup list bodies
- **Why:** Loading exists on Cleanup (`busy` bar). Empty rules/tweaks/startup lists and hard-fail messaging are not designed as first-class UI states.

### 7. No DESIGN.md / brand direction on disk
- **Priority:** HIGH
- **Rule:** R-37
- **Where:** repo root
- **Why:** UI work proceeds without written identity. Any polish pass should either add a short `DESIGN.md` from the existing dark utility look + Cleanup screenshot, or stay labeled draft.

### 8. Cleanup row grid is the alignment reference (keep / mirror)
- **Priority:** MEDIUM
- **Rule:** R-05, R-31
- **Where:** `CleanupPage` row `HorizontalLayout` (checkbox → fixed 360px name → `RiskBadge` 88px → spacer → size/files)
- **Why:** Screenshot shows the intended column lock. Do not “redesign” Cleanup away from this. Settings (and optionally Optimize status chips) should borrow the same density: top-aligned content, fixed columns, no equal stretch between labels.

### 9. Disclaimer uses em-dash risk copy that also fails tone tightness
- **Priority:** LOW
- **Rule:** R-02 (overlap with #4), R-16
- **Where:** Settings footer string
- **Why:** After removing the em dash, keep the warning specific and short; pin it under the language/path block instead of the window bottom.
